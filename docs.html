TESSEL · MODULE DOCUMENTATION

Build a
module

A module is a GitHub repository. Someone runs one command, approves what it's allowed to do, and your commands appear in their server. Nothing restarts.

What Tessel is

Tessel is a Discord bot with no features of its own. Server admins install the ones they want, one server at a time. A module enabled in one server is invisible in every other — its commands don't appear, its code doesn't run, its data isn't shared.

Modules are untrusted third-party code. Yours runs in an isolated child process with no bot token, no database access and no filesystem. Everything it can do is declared in its manifest and approved by the admin before anything runs.

That constraint shapes the whole API, so it's worth reading The sandbox before you get far.

Your first module

Two files. A manifest, and the code.

module.json

{
  "id": "com.github.yourname.greeter",
  "name": "Greeter",
  "version": "1.0.0",
  "apiVersion": "1",
  "description": "Greets people, and counts how many times.",
  "author": "yourname",
  "repository": "https://github.com/yourname/greeter",
  "entry": "src/index.ts",
  "permissions": ["storage"],
  "commands": [
    { "name": "greet", "description": "Say hello" }
  ]
}

src/index.ts

import { defineModule } from '@tessel/sdk';

export default defineModule({
  commands: {
    async greet(ctx) {
      const count = Number(await ctx.storage.get('greetings') ?? '0') + 1;
      await ctx.storage.set('greetings', String(count));
      ctx.reply(`Hello! That's greeting number ${count} in this server.`);
    },
  },
});

Push it to GitHub. That's the whole module — there is no build step, no package.json, and no dependency to install. Tessel bundles your TypeScript itself at install time.

You don't install @tessel/sdk. It's bundled in for you from the bot's own copy, which is also why a module can't ship a doctored version of it. Your editor will complain it can't find the import; that's expected.

Installing a module

Anyone with Manage Server can install from a GitHub URL.

/module install https://github.com/yourname/greeter
/module load greeter
CommandWhat it does
/module install <url>Installs from GitHub, pinned to a commit. Warns if unreviewed.
/module load <module>Shows the permission list, then turns it on here.
/module unload <module>Turns it off. Commands disappear from this server.
/module listWhat's installed here, and what's on.
/module info <module>What it does, what it can do, which commit it's pinned to.
/module uninstall <module>Removes it and everything it stored here.

Commands

Commands are declared in the manifest as data, not code. That's deliberate: it lets Tessel register your slash commands with Discord without ever executing your code.

It also means adding a command needs a version bump and a /module update, not just a code change.

Every command in the manifest needs a handler of the same name. A declared command with no handler replies "Unknown command"; a handler with no manifest entry is unreachable, because Discord was never told it exists.

Command options

"commands": [{
  "name": "warn",
  "description": "Warn a member",
  "options": [
    { "name": "member", "description": "Who", "type": "user", "required": true },
    { "name": "reason", "description": "Why", "type": "string" }
  ]
}]

Types are string, integer, number, boolean, user, channel and role. user, channel and role arrive as ids.

Command names must be lowercase, 1–32 characters, letters/numbers/hyphens/underscores — Discord's rule, not ours.

Options are user input. Anything someone can type reaches your handler. Validate it — sides could be 0, -5 or 1e9.

Events

Events arrive without anyone running a command.

export default defineModule({
  events: {
    async memberJoin(ctx) {
      const channel = await ctx.storage.get('welcomeChannel');
      if (channel) await ctx.sendMessage(channel, `Welcome ${ctx.member.username}!`);
    },
  },
});
EventContextNeeds
memberJoinctx.member, ctx.memberCountevents.guild
memberLeavectx.member, ctx.memberCountevents.guild
messageCreatectx.messagemessages.read
messageDeletectx.messagemessages.read
voiceStateUpdatectx.voicevoice.read

If you lack the permission an event requires, you are not sent it — you don't receive it and discard it.

Nobody is waiting on an event, so a handler that throws has nowhere to report. The error is swallowed rather than killing the process for every server using your module. Crash repeatedly and the supervisor disables you.

Events need privileged intents on the bot. Member events require the operator to run Tessel with PRIVILEGED_INTENTS=members, and message content requires messageContent — both also enabled in Discord's Developer Portal. Say so in your README, or people will install your module and wonder why nothing happens.

The context object

Every handler gets a ctx. It carries information about where it's running, and every action you're allowed to take.

PropertyWhereWhat
ctx.guildIdeverywhereThe server. Set by Tessel; you can't influence it.
ctx.guildNameeverywhereIts display name.
ctx.userIdcommandsWho ran it.
ctx.optionscommandsWhat they filled in.
ctx.reply(text)commandsAnswers them. Call once.
ctx.membermember eventsid, username, displayName, bot, createdAt
ctx.messagemessage eventsid, channelId, content, author
ctx.voicevoice eventsmember, channelId, previousChannelId

If your handler finishes without replying, Tessel replies "Done." so nobody is left watching a spinner. If it throws, the user gets a short failure message and the details go to the bot's logs — never to them.

Storage

const notes = JSON.parse(await ctx.storage.get('notes') ?? '[]');
notes.push({ by: ctx.userId, at: Date.now() });
await ctx.storage.set('notes', JSON.stringify(notes));

A per-server key/value store, namespaced to your module. Values are strings — use JSON.stringify for anything richer. Needs storage.

  • Per server. The same key in two servers holds two different values.
  • Per module. Another module using notes doesn't see yours.
  • Quota'd. storage.quotaKb per server, 512KB by default. A write that would exceed it is refused and your set() rejects.

HTTP

// module.json
"permissions": ["http"],
"network": ["api.example.com"]
const response = await ctx.fetch('https://api.example.com/thing');
if (response.ok) {
  const data = JSON.parse(response.body);
}

Needs http. Returns { status, ok, body }.

  • https only.
  • Only hostnames listed in your network field. That list comes from your manifest, so you can't widen it at runtime.
  • Redirects are refused — a permitted host that redirects elsewhere would otherwise be a way around the list.
  • 10 second timeout, response capped at 100KB.

This is the permission that lets a module move data off the server. Admins are told exactly which hosts you listed. Ask for as few as possible.

Raw API

const emojis = await ctx.raw('GET', `/guilds/${ctx.guildId}/emojis`);

The escape hatch, for anything the SDK doesn't cover. Needs discord.raw.

Tessel injects the token and refuses any route not scoped to the calling server, so this means anything within this server, not anything. Only /guilds/… naming your guild and /channels/… resolving inside it are allowed. /users, /applications and global endpoints are refused.

The consent screen calls this out loudly, and rightly. Expect fewer installs if you ask for it. Prefer a specific SDK method where one exists — and if something's missing, that's worth reporting rather than working around.

Permissions

Your module gets nothing by default. Every capability is requested in the manifest and approved by the admin, who sees this wording before saying yes.

PermissionWhat the admin is told
messages.readRead the content of messages sent in this server.
messages.sendSend, edit and delete its own messages.
messages.manageDelete other people's messages.
reactionsAdd and remove reactions on messages.
members.readSee the list of members and their profile details.
members.rolesGive and take away roles from members.
members.moderateTime out or kick members from this server.
members.banBan and unban members from this server.
channels.readSee the list of channels and their settings.
channels.manageCreate, edit and delete channels.
events.guildBe notified when members join or leave this server.
voice.readSee who joins, leaves and moves between voice channels.
storageSave its own data for this server.
httpContact the internet addresses listed in the manifest.
discord.rawMake any Discord request within this server.

Ask for as little as possible. The permission list is the main thing a cautious admin reads, and the dangerous ones are called out separately and more loudly. A module asking for discord.raw when it only needed messages.send will be installed by fewer people.

Use a capability you didn't request and the call fails at runtime, with the refusal written to that server's audit log.

Per-server isolation

One process serves every server that enabled your module — isolation is enforced per call, not by running a copy per server.

You never pass a guild id to an action. ctx.guildId is stamped by Tessel, and every action resolves through the server the command or event came from. A module cannot reach a server it wasn't invoked from, even deliberately.

The same applies to storage, warnings, settings — everything is keyed by server, and no query can return one server's rows to another.

The sandbox

Your module runs in a locked-down child process. Two independent layers, and an escape has to defeat both.

You cannot:

  • import node:fs, net, http, child_process, worker_threads, os, vm, process or similar. The bundler rejects these at install time with a clear error.
  • Use fetch, WebSocket or XMLHttpRequest — they don't exist. Outbound HTTP is a brokered call.
  • Read process.env, the bot token, or the database.
  • Depend on npm packages. There is no node_modules. Need a library? Vendor its source into your repo where a reviewer can see it, and import it relatively.
  • Use eval or new Function.

You can import node:path, url, util, buffer, crypto, events, stream, zlib, assert, timers and string_decoder — everything pure and local. setInterval works normally.

Reviewed & unreviewed

Every module is reviewed or unreviewed. There's no third state.

A signature covers your module id, version, the exact commit and the hash of the built bundle — deliberately not the repo URL, because tags move and branches get force-pushed. Retag or amend after review and the hash changes, so your module drops back to unreviewed until it's looked at again. That tamper-evidence is the whole point: a signature can't be inherited by code nobody read.

Unreviewed modules still install. The person installing is told plainly that nobody has reviewed the code and it could be malware, and has to click through it. Many will. Some won't.

Publishing

Push to GitHub. That's it — there's no registry to publish to and no account to make. Anyone can install from your URL immediately.

To get listed on the catalogue, open an issue from that page with your repository URL and a one-line description.

Versioning

Your module is installed from a specific commit, resolved at install time. Moving a tag doesn't change what anyone already has.

  • Bump version for every release. Patch for fixes, minor for new commands, major for breaking changes to how commands behave.
  • Tag releases so people can pin one: /module install https://github.com/you/yours/tree/v1.2.0
  • If a new version asks for more permissions, the admin is asked to approve again. Adding permissions in a patch release is a good way to have your update declined.

Troubleshooting

'node:fs' is not available inside the module sandbox

You imported something the sandbox denies. See The sandbox.

modules may not depend on npm packages

There's no node_modules at runtime. Vendor the source into your repo and import it relatively.

it resolves outside the module directory

A relative import climbed above your repo root with ../. Everything you import must live inside your module.

module.json — permissions.0: Unknown permission 'x'

Check the spelling against Permissions. The error names the value it rejected.

declares network hosts but does not request the 'http' permission

Add "http" to permissions, or remove the network entry. Listing hosts you can't reach would mislead the admin approving your module.

My command doesn't appear

Commands come from the manifest. Bump version, push, have the admin run /module update, then check /module info.

My event handler never fires

Either you didn't request the permission it needs, or the bot isn't running with the privileged intent that makes those events exist. See Events.

My module was auto-disabled

It crashed or stopped responding three times within five minutes. The person who installed it is told why.
